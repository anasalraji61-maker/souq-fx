# نشر باك-إند MATRIX على استضافة عامة — لماذا هذا حاسم للإطلاق

**اكتُشفت هذه الفجوة أثناء مراجعة جاهزية الإطلاق (2026-09-16، محادثة مباشرة).**

## المشكلة بالضبط

الباك-إند (`backend/`) حالياً يشتغل فقط محلياً على لابتوب أنس:

- `mobile/app.json` → `extra.apiUrl` مضبوط على `http://192.168.8.104:8110` — عنوان **شبكة محلية
  خاصة** (192.168.x.x)، غير قابل للوصول من أي جهاز خارج نفس شبكة الواي فاي.
- `desktop/main.js` → نفس الشيء افتراضياً (`127.0.0.1:8110`)، والويب المحمَّل بداخله
  (`WEB_URL`) أيضاً `127.0.0.1:8081` — أي أن ملف exe الحالي مجرّد غلاف يفتح متصفحاً داخلياً على
  سيرفر Expo المحلي، ولن يعمل إطلاقاً على أي جهاز غير جهاز أنس نفسه وقت تشغيل السيرفر.

**النتيجة**: بالوضع الحالي، حتى لو نُشر التطبيق على App Store/Google Play أو وُزِّع ملف exe/dmg،
**لن يعمل لأي مستخدم حقيقي** — كل الميزات المتصلة بالخادم (تسجيل دخول، شموع حقيقية، تنبيهات،
واتش-ليست، عمولات، …) ستفشل فوراً لأنها تحاول الوصول لعنوان لا يوجد إلا داخل شبكة أنس المنزلية.

هذا أهم عائق تقني حالياً — أهم حتى من صقل الواجهة، لأن واجهة مثالية بلا خادم يعمل عامةً عديمة
الفائدة لأي مستخدم خارج شبكة أنس.

## الحل المطلوب (يحتاج قرار/حساب أنس — لا يقدر Claude يكمله بمفرده)

1. **اختيار استضافة** للباك-إند (يدعم FastAPI + WebSocket + قرص دائم لملف `matrix.db`):
   - **Railway** أو **Render** — أسهل للبدء، باقة مجانية محدودة كافية للاختبار المبكر، ترقية
     مدفوعة بسيطة لاحقاً. الخيار المُوصى به لضيق الوقت (أسبوعان).
   - **Fly.io** — مشابه، دعم جيد للـWebSocket والأقراص الدائمة.
   - **VPS عادي** (DigitalOcean/Hetzner/Linode) — أقصى تحكم لكن يحتاج إعداد يدوي أكثر (nginx،
     شهادة SSL، إلخ) — غير مناسب لضغط الوقت الحالي إلا لو عنده خبرة سابقة بهذا.
2. **حساب + نطاق (domain)**: يحتاج حساب أنس الشخصي على المنصة المختارة (بريد/دفع أحياناً) — قرار
   تكلفة حقيقية، لا يقدر Claude ينشئه.
3. **قرص دائم (persistent volume)** لملف `matrix.db` — بدونه، كل إعادة نشر تمحو كل بيانات
   المستخدمين المسجَّلين والتنبيهات المحفوظة من الصفر. كل المنصات أعلاه تدعم هذا لكن يحتاج تفعيلاً
   صريحاً بإعدادات المشروع على تلك المنصة.
4. **مفاتيح API** (Twelve Data، OpenRouter، ElevenLabs إن استُخدمت) — تُضبط كمتغيرات بيئة (environment
   variables) على منصة الاستضافة، بنفس أسماء `.env.example`، **بدل** ملف `.env` محلي.
5. **بعد النشر**: يجب تحديث:
   - `mobile/app.json` → `extra.apiUrl` للرابط العام الجديد (وإعادة بناء/نشر تحديث Expo).
   - `desktop/main.js` → قيم `WEB_URL`/`API_URL` الافتراضية (أو تمريرهما كمتغيرات بيئة وقت البناء).

## ما جهّزه Claude مسبقاً (كودي بحت، جاهز فور اختيار المنصة)

- `backend/Dockerfile` — صورة Docker بسيطة قياسية (Python 3.12 + `requirements.txt` +
  `run_api.py`)، متوافقة مباشرة مع Railway/Render/Fly.io (الثلاثة تدعم نشر Dockerfile مباشرة بلا
  إعداد إضافي).

بمجرد قرار أنس للمنصة وإنشاء الحساب، النشر الفعلي خطوات قليلة قياسية (ربط المستودع أو رفع الصورة)
— ثم Claude يكمل خطوة تحديث `app.json`/`desktop/main.js` بالرابط الجديد فور توفره.

## 🔴 الرابط العام يجب أن يكون **https** لا http (وإلا فشل التطبيق المنشور كلياً — 2026-09-22)

`extra.apiUrl` اليوم `http://192.168.8.104:8110`، وتبديله لاحقاً برابط عام **بـhttp** يبدو ناجحاً
على جهاز التطوير ويفشل فشلاً كاملاً بالنسخة المنشورة:

- **iOS**: سياسة App Transport Security تمنع أي اتصال بـ`http://` بنسخة الإصدار افتراضياً، ولا
  استثناء بـ`app.json` (`infoPlist` فيه `ITSAppUsesNonExemptEncryption` فقط). كل طلب — دخول،
  شموع، تنبيهات — يُرفض قبل أن يغادر الجهاز. وطلب استثناء ATS من أبل يحتاج تبريراً بالمراجعة
  ويُرفض عادةً لتطبيق ماليّ، فالحل هو https لا الاستثناء.
- **أندرويد**: النصّ الصريح ممنوع افتراضياً كذلك من targetSdk 28 فصاعداً بلا إعداد صريح.
- **سطح المكتب**: يعمل بـhttp تقنياً، لكن رابطاً واحداً للجميع أبسط من رابطين.

Railway وRender وFly.io تعطي نطاقاً بشهادة https جاهزة بلا عمل إضافي — فهذا مجاناً بأيٍّ منها.
**VPS عادي وحده يحتاج انتباهاً**: شهادة (Let's Encrypt/Caddy/nginx) قبل ربط التطبيق به، وإلا
كان الباك-إند «منشوراً» والتطبيق لا يصله. ولا يُسلَّم أي بناء للمتجرين قبل أن يكون الرابط
`https://…` ومُجرَّباً من خارج شبكة أنس.

## مراجعة بلاغات المحتوى (شرط أبل 1.2 — 2026-09-22)

محادثة المجموعة وأفكار الصفقات محتوى ينشئه المستخدمون، وأبل تشترط إبلاغاً + حظراً + **تصرّف المطوّر
على البلاغات خلال 24 ساعة**. ما هو جاهز: زر «⋯» على كل رسالة/فكرة (إبلاغ أو حظر محلي)، العنصر يختفي
عند المُبلِّغ فوراً وعن الجميع بعد بلاغات 3 حسابات مختلفة، والروابط مرفوضة عند النشر.

للمراجعة اليدوية: اضبط متغيّر البيئة `MATRIX_MODERATION_TOKEN` بقيمة سرية طويلة على منصة الاستضافة
(بدونه المسار غير موجود — 404). ثم:

```bash
# قائمة البلاغات (العنصر، عدد البلاغات، الأسباب، النص، هل أُخفي عن الجميع)
curl -H "X-Moderation-Token: $TOKEN" https://<api>/api/moderation/reports
# حذف نهائي لعنصر مسيء، أو إسقاط البلاغات عنه ("dismiss") فيعود ظاهراً
curl -X POST -H "X-Moderation-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"group_message","target_id":"<id>","action":"remove"}' https://<api>/api/moderation/action
```

## تغليف تطبيق سطح المكتب الفعلي (exe/dmg) — خطوات ينفّذها أنس يدوياً (2026-09-16)

**لماذا يدوياً**: Claude لا يقدر يشغّل أوامر بناء (npm/expo/electron-builder) على جهاز أنس مباشرة —
فقط تعديل الكود ومراجعته. `desktop/` (Electron shell) و`desktop/build/icon.ico`+`icon.icns`
(أيقونات حقيقية مولَّدة من `mobile/assets/icon.png` هذا التشغيل) جاهزان بالكامل كودياً، الخطوات
التالية فقط بناء فعلي محلي:

1. **تصدير واجهة الموبايل كويب** (من مجلد `mobile/`):
   ```
   cd mobile
   npx expo export --platform web
   ```
   يُنتج مجلد `mobile/dist/` (حزمة ويب ثابتة قابلة للتشغيل بلا خادم Metro حي).
2. **نسخ الحزمة إلى `desktop/web-build/`** (الاسم الذي يقرأه `desktop/main.js` فعلياً —
   `BUNDLED_WEB_INDEX` سطر 14):
   ```
   xcopy /E /I mobile\dist desktop\web-build
   ```
   (أو نسخ يدوي عادي بمستكشف الملفات — المهم اسم المجلد `web-build` بالضبط داخل `desktop/`).
3. **تثبيت تبعيات Electron** (مرة واحدة، أو بعد أي تحديث لـ`desktop/package.json`):
   ```
   cd desktop
   npm install
   ```
4. **تجربة سريعة قبل البناء** (اختيارية لكنها تكشف عطباً قبل إنتاج حزمة كاملة): من `desktop/`
   `npm start` يفتح التطبيق بالنسخة المضمَّنة إن وُجدت، و`npm run dev` يفتحه محمَّلاً حيّاً من
   `MATRIX_WEB_URL`. **الأمران يعملان على ويندوز وماك ولينكس معاً** (`electron .` من `node_modules/.bin`
   والراية `--dev` بدل `set` الويندوزية) — وهذا ما يسمح بتجربة التطبيق على الـMac الذي يُبنى عليه
   الـdmg بالخطوة التالية. `start-desktop.bat` بجذر المستودع يبقى كما هو لتشغيل ويندوز بنقرة.
5. **البناء الفعلي**:
   - ويندوز (exe): `npm run dist` — يُنتج `desktop/dist/MATRIX-Charts-Setup-<version>.exe`
     (مثبِّت NSIS، أيقونة `build/icon.ico` مضمَّنة تلقائياً حسب إعداد `package.json`).
   - ماك (dmg): `npm run dist:mac` — **يجب تشغيله على جهاز Mac فعلي** (`electron-builder` لا يقدر
     يبني حزمة `.dmg` موقَّعة من ويندوز/لينكس) — يُنتج `desktop/dist/MATRIX-Charts-<version>.dmg`.
6. **قبل التوزيع العام**: راجع بند (ب.7) بـROADMAP.md — بلا توقيع رقمي، ويندوز يُظهر تحذير
   SmartScreen وماك يرفض التشغيل عبر Gatekeeper حتى يتجاوزه المستخدم يدوياً؛ مقبول مؤقتاً لضيق
   الوقت لكن قرار التوقيع (تكلفة حقيقية) يبقى قرار أنس.
7. **تنويه مهم**: خطوة النشر العام للباك-إند (القسم أعلاه) **يجب أن تتم أولاً** — بناء exe/dmg بدون
   خادم عام يبقى غير مفيد لأي مستخدم خارج شبكة أنس (نفس المشكلة الموضَّحة بالأعلى)، فحدِّث
   `desktop/main.js` (`WEB_URL`/`API_URL`) بالرابط العام النهائي **قبل** الخطوة 1 أعلاه، لا بعدها.
