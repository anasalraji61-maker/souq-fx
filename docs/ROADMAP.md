## توجيه "مطابقة ميزات TradingView" (2026-09-10)
طلب أنس أن تحتوي MATRIX كل ميزات TradingView. **التفسير المعتمد** (يماشي حذره القانوني الخاص):
**التكافؤ الوظيفي — نفس القدرات، بتصميم وكود وتسمية MATRIX الأصليين بالكامل — وليس نسخ واجهة
TradingView أو علاماتها أو تخطيط شاشاتها حرفياً.** هذا التفسير هو الوحيد المتوافق مع
ip-legal-caution.mdc الذي وضعه أنس نفسه، وهو ما استمر عليه العمل منذ بداية المشروع.

**استثناء محفوظ من نطاق العمل (وليس فجوة تكافؤ):** تنفيذ صفقات فعلي / ربط وسيط — هذا يبقى خارج
MATRIX تماماً، بحكم الفصل المتعمّد أصلاً بين MATRIX (تحليل/شارتات فقط) وMatrixRobot (التنفيذ).
توسعة MATRIX لتنفيذ صفقات حقيقية تُلغي هذا الفصل المعماري المتعمَّد — قرار كبير يحتاج تأكيدك
الصريح لو تغيّر رأيك بهذا الخصوص تحديداً، وليس تكافؤ ميزات عادي.

## المبدأ

1. الموثوقية أولاً زمنياً (أساس ثابت) — التصميم والميزات تُبنى فوق أساس مستقر، لا بدلاً منه.
2. Claude يقرر بذوقه وبجدول التكافؤ أعلاه ضمن ip-legal-caution.mdc وmatrix-tactile-feel.mdc،
   ومعزول تماماً عن روبوت التداول/MT5.
3. كل تعديل مهمة HANDOFF واحدة صغيرة قابلة للتحقق. فجوة كبيرة بالجدول (مثل Pine Script) تُجزَّأ
   لعدة مهام صغيرة متتالية، لا مهمة واحدة ضخمة غير قابلة للمراجعة.
4. عمود "يحتاج إذن" في الجدول أعلاه = تكلفة مالية أو ترخيص/قانون جديد فعلاً، وليس مجرد كبر حجم
   العمل — حجم العمل وحده لا يوقف التنفيذ التلقائي.

الأنماط المجاورة + تحقّق حسابي يدوي قبل الاعتماد): **MFI** (مؤشر تدفق مالي حجمي، نمط RSI الحجمي)

صارمة، لا بديل عن المقارنة المباشرة بين الاستيراد الفعلي والتصدير الفعلي لكل دالة جديدة قبل تسجيلها
كمكتملة — ادّعاء "تحقّقت بالقراءة" بلا ذكر الملف المقروء تحديداً غير كافٍ.
